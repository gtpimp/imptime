Sprints and core development

  • Sprints are the lifeblood of the development process.
  • They organise everything that has to be done (called issues) into manageable 3 week batches.
  • This focuses the attention and provides a continuous reality check.
  • Each issue has a time estimate, based on the cost estimate during budgetting.
  • Developers clock in and out of issues, with minute-level accuracy.
  • On the imptime sprint dashboard you can see the current over- or under- time on each issue and for the sprint as a whole
  • Also at any time the total budget under-run or over-run is available
  • Developers maintain code quality by writing tests
  • and running code reviews after each issue.
  • We release often and regularly. The first time any code is installable and runnable, it is installed and run so the client can start engaging with it.
  • Sprints always achieve at least one visible change and at least milestone target
